# 016 — Unmatched fallback should return 404, not 500

**Status**: BACKLOG.
**Severity**: LOW (behavioral / minor info leak).
**Effort**: 5 minutes.
**Filed**: 2026-06-17.
**Discovered while**: verifying admin-gate behavior for #008.

## What's wrong

`src/router/mod.rs::handle_request` is registered as the axum
fallback. For any unmatched request (e.g. `GET /_/sources` when the
admin endpoint isn't mounted, or `GET /nonexistent/path`) the handler
walks the DSL map, fails to find one, and returns:

```
HTTP 500 {"error":"File not found: DSL not found: GET/_..."}
```

That's wrong on two counts:

1. **It's a client error, not a server error.** 500 indicates the
   server failed to process a valid request. A missing route is a
   404.
2. **It leaks shape information.** The body tells the caller this is
   a Ruuter instance, that DSL lookup happened, and what key was
   tried. For an external-facing gateway, that's a small but real
   reconnaissance signal.

## Fix

Map the specific `RuuterError::FileNotFound` to a 404 with a generic
body (`{"error":"Not Found"}`) in `handle_request`. Other errors
continue to map to 500.

## Verification

- `curl /nonexistent` → 404 with `{"error":"Not Found"}`.
- A genuinely-erroring DSL (e.g. malformed JS expression) still
  returns 500 with the original error message.

## Why this is generic

HTTP status correctness. No service-specific knowledge.
